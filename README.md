# Minecraft 模组云端同步（MinecraftModsCloudSync）

一套双端工具，用于在 **服务端（维护者）** 与 **客户端（玩家）** 之间同步 Minecraft 模组、资源包、配置等文件。

- **服务端工具**：管理服务器文件仓库，检测改动、制作待办、把新客户端内容同步上服务器、导出客户端配置文件。
- **客户端工具**：导入服务端下发的配置文件，自动检查并应用更新。

## 功能特性

### 服务端工具
- **多服务器管理**：同一界面管理多台服务器，每台服务器独立 SFTP 连接与远程目录；支持拖入版本文件夹 / `.minecraft` / 启动器快捷方式（PCL2 / PCL CE / HMCL）自动识别版本并入库；服务器列表支持搜索过滤、多选与反选、右键重命名 / 移除、侧边栏折叠。
- **更新服务端（C2S）**：自动创建服务端快照并对比本地新客户端，差异树展示新增（绿）/ 替换（橙）/ 删除（红）/ 旧版残留；旧版识别按「模组键」归一化（兼容 `2.6.2b`、`+mc`、`-neoforge`、大小写/下划线差异），`.bak` / `.temp` / `.new` / `.disabled.<时间戳>` 归类为「临时/备份」可一键清理；**多连接并行扫描 + 哈希**（「设置 → 扫描性能」可调 1~8 条连接，主连接也算一条；被小主机拒绝并发时自动降级），扫描速度显著提升；支持忽略、手动标注发送目标（双端 / 服务端 / 客户端 / 跳过）、模组运行环境分析（jar 元数据 + MC 百科标注）；「联网核对」用 Modrinth / CurseForge 的项目文件列表确认旧版身份、识别「服务端反而更新」并发现文件名规则漏掉的旧版。
- **发布待办（S2C）**：自动检测服务端改动并生成发布清单（新增 / 替换 / 删除 / 旧版残留），可禁用 / 启用 / 批注任务，发布后自动更新基线；检测同样走多连接并行扫描。
- **自动同步（免待办）**：服务端直接规定客户端可对比 / 自动下载的目录与文件（白名单 + 黑名单，支持 glob、`**`），支持扫描预览；客户端无需等服主发布待办，定时或手动直连服务器对比并自动拉取差异。客户端只下载、不删除本地文件。
- **文件管理（手动）**：直接管理服务器上的模组 / 资源包 / 光影包 / 插件 / 配置等文件——按分类展示，一键启用/禁用（服务器上改 `.disabled` 后缀，与 PCL 一致）、重命名、新建目录、删除（可选进服务器回收站）；支持从资源管理器**拖拽上传**文件/文件夹，上传前检测同名冲突；**所有操作都直接在服务器上完成，不会把服务端文件下载到本地**。另提供「映射为本地磁盘（给 PCL 用）」帮助：检测本机 SSHFS-Win / rclone 并生成映射命令，把服务器目录变成本地盘符，方便 PCL 直接把整合包下载到服务器中转。
- **快照历史**：每次更新服务端 / 发布待办都会保留一条带时间戳的历史快照，可查看任意快照的树状结构，也可将某个历史快照设为发布基线，从而撤销 / 回滚客户端更新。
- **历史版本（回收站）**：可选在删除 / 替换文件前把旧文件备份到服务器隐藏目录 `.mc-sync-history`，按「每条路径保留 N 个版本」+「历史目录总大小上限」自动清理，也可在界面里查看 / 还原 / 删除 / 清空；历史目录不参与扫描与发布，不会占用活动文件的空间。
- **服务器设置**：SFTP 连接信息、远程目录（服务端文件仓库根目录 / 待办目录 / 客户端文件目录，均为绝对路径）、差异排除规则、客户端模组关键词、客户端软件设置下发（自动检查间隔 / 开机自启 / 系统通知）；「设置」窗口另提供扫描并发连接数（1~8）。
- **导出客户端配置**：为每台服务器生成加密的配置文件（含唯一编号），授权编号同步到服务器。
- **日志**：按天查看、按时间段导出；日志按服务端 / 客户端隔离存储。

### 客户端工具
- **导入服务器配置**：支持拖入 `.mcscf` 配置文件自动导入（重复导入会提示覆盖），或通过文件对话框导入。
- **自动更新检查与应用**：按设定间隔自动检查各服务器更新，可一键应用（下载 / 替换 / 删除），服务端下发的软件设置自动生效。
- **自动同步（免待办）**：可开关的定时直连拉取；服务端规定同步范围，客户端只下载允许的目录/文件，本地多余文件只提示、不删除。也可随时点「立即检测并拉取」。
- **已知版本库**：拖入 `.minecraft` / `versions` 文件夹 / 启动器快捷方式自动识别版本；「选择已知版本…」快速设置客户端根目录。
- **安全**：服务器 SFTP 信息加密保存、日志脱敏（客户端日志不出现任何 SFTP 服务器细节）。

### 通用
- 深色 / 浅色双主题（跟随系统）。
- 所有表格 / 树表头支持拖动调整列序，列分隔线清晰。
- 搜索框统一支持 `*` 通配，实时过滤。
- 客户端与服务端启动即最大化；关闭窗口最小化到系统托盘。
- 开机自启（最小化到托盘）。
- 软件本体自动更新：定时（启动时 + 每 6 小时）从 **GitHub / Gitee** 双源检测新版本，GitHub 不可达时自动切换国内 Gitee 发行版；一键下载 Windows 安装程序（后台下载 + 进度条 + 更新日志）并自动启动安装；可在「设置」中关闭自动检查。

## 使用流程（简要）

1. **服务端**：添加服务器 → 在「服务器设置」填写 SFTP 连接信息与远程目录 → 在「更新服务端」页把新客户端内容同步到服务器文件仓库 → 在「发布待办」页检测改动并发布待办（或改用「自动同步（免待办）」页下发范围）→ 在「导出客户端配置」页生成配置文件发给玩家。
2. **客户端**：导入服务端下发的配置文件 → 选择本地 Minecraft 根目录 → 「立即检查更新」→「应用更新」；如需免待办直连拉取，在「自动同步」分组打开开关并设置检测间隔。

## 目录结构

```
app_common/     # 双端共用：配置、日志、SFTP、快照、版本解析、任务清单、自动同步策略、模组分析等
client_app/     # 客户端：主窗口 + 更新引擎
server_app/     # 服务端：主窗口 + 各工作流页面
assets/         # 图标素材
installer/      # Inno Setup 安装脚本
build.py        # PyInstaller 打包脚本（生成单文件 exe）
```

## 构建与打包

```bash
# 1) 安装依赖
pip install -r requirements.txt

# 2) 打包客户端与服务端单文件 exe（输出到 dist/）
python build.py

# 3) 编译 Windows 安装程序（需安装 Inno Setup）
ISCC installer/setup.iss
```

Release 产物：
- `MinecraftSyncClient.exe` — 客户端单文件
- `MinecraftSyncServer.exe` — 服务端单文件
- `MinecraftModsCloudSync_Setup_1.0.0.exe` — Windows 安装程序

## 技术栈

- Python 3 + PySide6（Qt）图形界面
- paramiko（SFTP）
- PyInstaller（单文件打包）
- Inno Setup（安装程序）

## 说明

- 服务端与客户端通过 SFTP 交换数据：待办清单（`manifest.json`）、客户端文件仓库、授权编号清单、C2C 共享文件区（`.upload_files`）。
- 客户端配置文件为加密存储，仅服务端导出的配置文件可被客户端识别。
