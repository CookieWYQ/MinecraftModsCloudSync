# v1.2.7 更新内容

本版重点解决「用起来迷迷糊糊」的问题：让软件能自己判断文件该去客户端还是服务端、让快照回滚变得看得懂、让我们对检测结果有信心。

## 一、发送前自动检测模组运行环境（新增）

在「更新服务端」页点「发送」时，会先对本次要上传的 mods 目录下的 `.jar` 逐个判定运行环境，再决定它该去哪个位置：

- **客户端模组** → 只发客户端文件目录 `client_files/mods/`
- **服务端模组** → 只发服务端 `mods/`
- **双端模组** → 两边都发

判定依据按优先级：

1. **本地 jar 元数据**（最快）：Fabric / Quilt 的 `environment` 字段；Forge 1.12 及更早的 `mcmod.info` 中的 `clientSideOnly` / `serverSideOnly`
2. **MC 百科**：元数据判不出的（Forge / NeoForge 等）联网抓取百科「运行环境」标注

这一步的目的就是**防止客户端模组被误传到服务端的 mods 目录里**。判定结果会在确认框里逐条列出依据（例如「fabric.mod.json 标注 environment=client」）。

## 二、判定不出来的模组不再被静默放过

- 之前判不出运行环境的模组会**无声无息地按「双端」发送**，界面上还会显示「运行环境与目标一致 ✔」——等于给了个假的检查通过。
- 现在，**没判定出来、却会被发到服务端 mods** 的模组，会在发送确认框里单独列出（附上未判定的原因），提醒你确认；确实有「仅客户端」的模组，可以点「取消上传」，在列表里右键改成「仅客户端」再发。
- 只有确实全部判定完成时才会显示 ✔。

## 三、默认发送目标改为「看服务端实际有哪些目录」

之前会根据文件名猜类别，容易把本该放服务端的文件（例如想让所有人都装的资源包）误判成仅客户端。现在改为**读服务端文件仓库根目录下真实存在的文件夹**：

- 服务端有 `resourcepacks/`（说明服务端在用）→ 该目录下的文件默认双端
- 服务端没有 `shaderpacks/`（服务端没在用）→ 默认仅客户端，**不在服务端凭空建目录**
- 鼠标悬停「目标」列会写明判定依据；右键可随时手动改成「双端 / 仅客户端 / 仅服务端」，手动标注永久优先

另外修了几个边界问题：服务端根目录**确实为空**与**目录列表读取失败**现在区分对待（后者会告警），不再一概按双端处理；空白关键词不再导致所有模组被误判为「仅客户端」。

## 四、自动纠正与手动标注分开，不再互相锁死

发送前检测自动改掉的目标会记在单独的地方，与手动标注互不干扰：

- 下次检测还能继续更新它（换了新版本模组会自动重新判定），不会再像「手动标注」一样被永久锁住
- 手动标注依然最高优先级；手动标注与运行环境冲突时**只提醒、不擅自改动**
- 右键「恢复自动标注」可同时撤销自动纠正与手动标注

## 五、「服务端模组归类…」按钮（新增）

服务端 mods 里已经混进了客户端模组？在「更新服务端」页点这个按钮，会：

1. 体检服务端 `mods/` 下所有模组，逐个分析运行环境
2. 挑出「仅客户端」的，移动到你指定的客户端文件目录 `client_files/mods/` 下
3. 搬运时自动把目标标注为「客户端」，以后不会再被传回服务端

**同名不代表同一个文件**：会先做「大小 + 哈希」比对，内容一致才用本地文件分析，否则才从服务端下载下来分析（一次目录体检省下大量流量）。

## 六、快照 / 撤销改成向导式回滚

原来的快照功能不好懂，本版重做为「发布历史 / 回滚…」向导：

- 顶部选择查看「发布历史」还是「仓库快照」
- 左侧点时间点，右侧直接看**差异树**：每个文件会标明回滚动作（删除 / 还原为旧版 / 需人工处理）与原因
- 底部一键「回滚到此时间点」，完成后自动回到发布页重新检测

## 七、发布页区分「客户端内容」与「服务端独有」

「发布给客户端」的变更树现在分两组显示，一眼能分清哪些是下发给客户端的：

- **① 将发布给客户端**（来自 `client_files`）
- **② 服务端独有，不下发**（服务端 `mods/` 里另有那些模组，灰显、不可勾选）

## 八、扫描与哈希提速

- **远程哈希改为流水线批量请求**：一次发出 32 个快速哈希请求再按序收响应，往返次数从「文件个数」降到「文件个数 / 32」
- **本地哈希缓存**：文件大小与修改时间都没变时直接复用上次的 MD5，重复扫描几乎零开销
- **多线程并行**：批量哈希用 3 个独立连接并行

## 九、断网环境不再卡住

联网查 MC 百科补齐运行环境时，之前逐个查询、断网会卡十几分钟。现在有三重保护：

- 单次请求超时 + **整体 45 秒预算**
- 连续多次网络失败即判定为无网络，**立即放弃其余查询**
- 模组数量上限，超出部分直接跳过

实测模拟断网：60 个模组只发 11 次请求、0.5 秒返回。另在「SFTP 设置」页新增开关「上传前联网查询 MC 百科…」，关掉则只用本地元数据，速度更快。

## 十、其它修复

- 百科「运行环境」文本解析重写：按「客户端 / 服务端」各自的**需装 / 可选 / 无需**分别判定。之前「客户端需装, 服务端可选」会把「可选」信息丢掉，现在百科原文会完整显示在提示里
- `fabric.mod.json` **缺少** `environment` 字段时，不再当成「确定双端」，而是按「未判定」处理——避免把「不知道」包装成「确定」
- NeoForge / Forge / 无元数据 / 损坏 jar 各自给出准确的判定失败原因，不再是统一一句「Forge 元数据不含运行环境字段」
