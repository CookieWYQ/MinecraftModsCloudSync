# v1.3.1 更新内容

## 新增：文件管理（手动）——右键打开模组网页

在「文件管理（手动）」页右键任意模组 jar（含被禁用的 `.jar.disabled`），新增「模组网页」子菜单：

- **MC 百科**：本地数据库能确认模组时直接打开详情页（`mcmod.cn/class/…`），确认不了就打开百科搜索页；
- **Modrinth**：能确认项目时直达 `modrinth.com/mod/{slug}`，否则打开 Modrinth 搜索页；
- **CurseForge**：能确认项目时直达项目页，否则打开 CurseForge 搜索页；
- 子菜单里还可分别复制三个网站的链接。

也就是说：**所有模组都能打开一个相关网页**——能确认项目的直达详情页，确认不了的用搜索页兜底，不联网也能解析（查的是随程序打包的 `mcmod.buf`）。此外在文件管理页给模组右键「启用/禁用、重命名、删除」等原有操作保持不变。

## 新增：文件管理（手动）——手动标记 / 排除

「文件管理（手动）」页右键条目 →「标记 / 排除」子菜单，树里新增「标记」列回显当前状态。三类标记都与对应页面共用同一份数据，标记后不需要再手动同步：

- **发布待办：本次不发布** —— 与「发布待办（S2C）」页右键「禁用（本次不发布）」完全相同；标记后该文件不参与改动检测，也不会被发布给客户端。
- **自动同步：排除** —— 写入服务器上的自动同步策略黑名单（`{待办目录}/auto_sync.json`），客户端自动同步时不再下载这些文件；选目录会覆盖整棵子树。只改黑名单，不会偷偷打开自动同步总开关；服务器还没有策略文件时会按默认「关闭」状态创建。
- **差异审核：跳过** —— 与「更新服务端（C2S）」页右键「标注为 → 跳过」等效：不扫描、不比对、不发送；切回更新服务端页会自动按新标记重新检测。

发布待办、自动同步、更新服务端三个页面在切回 / 重新检测时会读取这些标记，因此标记是即时生效的；「标记」列会同时显示「发布排除 / 同步排除 / 审核跳过」，鼠标悬停可看说明。取消标记同样是右键对应项再点一次。

## 其他

- 「更新服务端（C2S）」「发布待办（S2C）」以及服务端文件浏览树的右键菜单里，模组 jar 也同步加上 **Modrinth / CurseForge 网页**入口（原来只有 MC 百科），同样支持搜索页兜底。
- 「标记 / 排除」支持多选批量操作（发布待办标记仅对文件生效，目录请用另外两类标记）。
- 新增回归测试：`tests/test_mod_links.py`（模组网页链接与搜索页兜底）、`tests/test_file_manager_marks.py`（三类标记的写入/取消/菜单回显/跨页共用）。
- 同步更新 README、技术交接文档（文件管理章节、模块表、测试列表）。

# v1.3.0 更新内容

## 新增：多连接并行扫描 / 哈希（扫描大幅提速）

之前扫描服务端目录、计算远程哈希基本是「单连接逐目录 / 逐文件」，模组包一大就要等很久。本版把扫描和哈希都改成了多连接并行：

- 「更新服务端」的快照扫描、「发布待办」的实时检测、「自动同步」的策略预览、快照对话框，全部走多连接并行列目录 + 并行远程哈希；主连接也直接参与工作，不额外浪费一条连接。
- 新增「设置 → 扫描性能 → 并行连接数」（1~8，默认 6）：网络好、主机允许时可以调大明显提速；免费/小主机限制并发时调小即可。
- 服务器拒绝多余连接时自动降级（其余连接继续扫完），工作连接中途掉线会自动改用主连接串行重扫，**不会返回缺目录的半截结果**（避免把读不到的文件误判成「已删除」）。
- 服务器不支持 `check-file` 快速哈希时（很多面板服/小主机都是这样），回退逻辑从「下载到临时文件再算」改为**流式读取边收边算**，少一次磁盘写入/读取；多连接并行下载哈希是本次提速的主要来源。
- 「发布待办」检测改用严格扫描：任何目录读取失败都直接报错，不会静默漏文件。

## 新增：文件管理（手动）页

服务端工具新增「文件管理（手动）」标签页，用来直接打理服务器上的文件，**所有操作都在服务器上完成，不会把服务端文件下载到本地**：

- **分类展示**：模组 / 资源包 / 光影包 / 服务端插件 / 数据包 / 配置 / 默认配置 / 脚本，其余顶层条目归入「其他文件 / 目录」；可在「服务端目录」和「客户端文件仓库」之间切换。
- **启用 / 禁用**：一键给文件加/去 `.disabled` 后缀（与 PCL 等启动器一致），支持多选批量、也可对整分类批量操作；同名启用版/禁用版并存时判为冲突不覆盖。
- **拖拽上传**：从资源管理器把文件或整个文件夹拖到分类/子目录上即可上传，保留文件夹结构；上传前会检测同名冲突，让你选覆盖或跳过；隐藏项与 `.tmp` / `.part` 等临时文件自动跳过。
- **重命名 / 新建文件夹 / 删除**：删除文件时若开启了「历史版本（回收站）」，会先归档到 `.mc-sync-history` 再按策略清理；目录不进回收站（界面会提示）。服务端根目录顶层文件（start.sh 等）依旧受保护。
- **映射为本地磁盘（给 PCL 用）**：页内提供帮助窗口，检测本机 SSHFS-Win / WinFsp / rclone 并生成可直接复制的映射命令，把服务器目录（默认「客户端文件仓库」`client_files`，结构正好对应 PCL 的 mods/resourcepacks）变成 Windows 盘符。PCL 把「游戏目录」选到该盘符后，就能把整合包/模组直接下载进服务器中转。需要自行安装 SSHFS-Win（含 WinFsp）或 rclone；网络盘有延迟，建议只用来放 mods / resourcepacks 等文件，并注意 PCL 可能会在仓库里生成 versions/libraries 等文件（可在文件管理页清理）。

## 修复：客户端无法导入服务器配置文件（v1.2.14 引入）

- 修复「导入配置文件…」按钮和拖入 `.mcscf` 都没反应、日志里也没有任何记录的问题：导入函数的参数与调用处不一致，每次导入都会抛出异常，而窗口程序没有控制台，异常被静默吞掉。现已恢复导入，并把每个导入步骤（开始 / 读取或解析失败 / 取消 / 成功）写入日志，可在「日志管理…」中查看。
- 未导入任何配置时，客户端右侧不再显示无意义的空服务器详情，改为「尚未导入服务器配置文件」引导页 + 一键导入按钮。
- 拖入的配置文件即使扩展名被改写（如 `.txt`），也会按文件内容识别并导入；文件选择框增加「所有文件」筛选，避免选不到文件。
- 客户端增加未捕获异常日志兜底：以后任何界面异常都会写入日志，不再「静默失败」。
- 新增回归测试：`tests/test_client_import.py`（空状态引导 / 按钮导入 / 拖入导入 / 内容嗅探 / 取消导入 / 导入日志）。

## 其他

- 「设置」窗口新增「扫描性能」分组；服务端设置页保存后，文件管理页会同步刷新目录。
- 新增回归测试：`tests/test_parallel_scan.py`（并行扫描/哈希/策略/配置）、`tests/test_file_manager.py`（分类/启用禁用/重命名/删除回收站/上传/映射命令）。

# v1.2.14 更新内容

## 新增：自动同步（免待办直连拉取）

「发布待办」需要服主先检测改动、发布清单，客户端再按清单安装。本版新增一条更直接的链路：**服务端规定同步范围，客户端直接对比服务器文件仓库并自动拉取**，玩家不必等服主发布待办。

- 服务端新增「自动同步」页：总开关 + 白名单 + 黑名单（支持 glob、`**`），可扫描预览策略会命中哪些文件；白名单为空 = 不同步任何文件。
- 客户端新增「自动同步」分组：本地开关 + 检测间隔（5–1440 分钟），也可随时点「立即检测并拉取」；**只下载新增/变化文件，绝不删除本地文件**（本地多余文件只提示）。
- 跳过隐藏项与 `.tmp` / `.part` / `.crdownload` 等临时文件；下载目标做路径校验，拒绝路径穿越。
- 服务端策略开关 + 客户端本地开关两层都打开才生效；与「发布待办」链路互不影响。

## 新增：历史版本（服务端回收站）

「更新服务端」的删除以前是真删除、「替换」是直接覆盖，升级模组后旧版本再也拿不回来。本版新增服务端历史目录：

- 「服务器设置」可开启「删除 / 替换前备份旧文件」，并设置「每条路径保留 N 个版本」（默认 3）与「历史目录总大小上限」（默认 512 MB）。
- 旧文件用服务器内 rename / move 归档到 `{files_dir}/.mc-sync-history`，几乎不产生额外流量；纯新增不产生历史。
- 「更新服务端」页新增「历史版本…」：查看 / 还原 / 删除单条 / 清空全部 / 立即按策略清理；还原时若原路径已有文件，会先自动备份现有文件。
- 历史目录是隐藏目录，不参与扫描，也不会出现在差异列表与发布清单里。

## 新增：联网核对旧版文件（Modrinth / CurseForge）

「更新服务端」差异列表新增 **「联网核对…」** 按钮：不再只靠文件名猜新旧，而是把本地模组解析到发布渠道项目，取回该项目**全部版本的文件名列表**再判断。

- **确认旧版**：服务端文件名精确出现在项目文件列表里，且发布时间 / 版本号早于本地 → 绿色「确认旧版」，保持默认勾选。
- **服端更新**（重要）：服务端那份其实**比本地新**（例如服端 2.1.6、本地 1.2.4）时显示红色「服端更新」并**自动取消勾选**，避免删除后玩家被降级。
- **未收录**：Modrinth / CurseForge 都查不到（私有 mod、未公开构建）→ 灰色「未收录」，不影响原有勾选。
- **发现漏网旧版**：服务端独有文件若被联网确认属于本地已有模组项目（文件名规则没覆盖到的改名/换前缀），会追加为「旧版残留」，默认不勾选，供人工核对。
- 支持「服务端文件名被手动改名」（少了 `-neoforge` / `-mc1.21.1` 等后缀）：在同一项目内按加载器 / 游戏版本消歧后匹配。
- 渠道不需要 key：Modrinth 官方 API + CurseForge 只读接口 cfwidget。结果缓存 7 天，第二次核对基本零请求；断网 / 超时只降级为「未收录」，界面不会卡住。

## 修复：工具条按钮过多时右侧复选框被截断

「更新服务端」页按钮分为两行，窄窗口下「同步范围 / 历史版本 / 显示服务端独有」不再被挤出屏幕。

# v1.2.13 更新内容

安全修复：**服务端根目录下的顶层文件（start.sh、server.properties、eula.txt 等）绝不会被同步操作删除。**

## 问题

之前如果服务端根目录下有本地没有的文件（如 `start.sh`），它会被识别为「服务端独有」并出现在差异列表里。一旦勾选发送，就会被删掉——而这些是服务端的核心启动/配置文件，绝对不能碰。

## 修复（四道防护）

1. **差异列表阶段**：服务端独有的顶层文件/目录（路径不含 `/`，如 start.sh、lib、newforge）不列入差异列表，用户根本看不到、勾不到。
2. **改名匹配阶段**：顶层文件不会被当作「改名的旧文件」匹配删除。
3. **勾选联动阶段**：「服务端独有」的文件不参与父子勾选联动——勾父目录/根目录不会勾上它们，防止全选时把服务端核心文件（lib、newforge 等）误删。
4. **执行阶段硬拦截**：即使前三道被绕过，删除执行时遇到顶层文件直接跳过并记日志，绝不调用 SFTP 删除。

## 其他

- 上一版（v1.2.12）的「跳过 = 不扫描」逻辑保持不变。
- 建议把不想管的目录标为「跳过」，或用「同步范围」只圈 mods，从源头减少误操作风险。
