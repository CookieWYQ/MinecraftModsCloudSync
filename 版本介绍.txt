# v1.2.10 更新内容

本版一个安全修复、一个新功能。**如果你用「更新服务端」发文件，强烈建议更新。**

## 一、修复「改名」时会去删服务器根目录（危险，务必更新）

上一版有个隐患：把审核列表里某个模组右键点成「改名」（例如 `foo.jar` → `foo.jar.disabled`）后发送，程序会把旧文件名**丢掉**，于是「删除旧文件」的目标算成了服务端的**根目录 `/`**，日志里出现：

```
删除远程目录失败: / (failure)
```

服务器拒删根目录下仍在使用的文件，这次才没酿成事故；运气差一点就是整个服务端文件仓库被递归删掉。

根因是审核列表每一行漏记了「原名」。现在做了三层防护：

1. **源头修好**：改名行完整带上旧文件名，删除目标永远是那个具体的旧文件；
2. **宁可不删**：万一旧文件名仍然缺失，只记一条警告并跳过删除，绝不退化成删目录；
3. **远程兜底**：SFTP 层直接拒绝空路径 / `/` / `///` 作为删除目标，路径算错也删不掉根目录。

## 二、「更新服务端」新增「同步范围」：只扫你挑的那几个目录（取代旧的「忽略审查」）

之前每次发送都要**先全量扫完服务端仓库，再和本地整个客户端目录对比**——只想同步一个模组和几个资源包时，也要把 world、logs、截图、备份全部读一遍，又慢又没必要。

现在可以在审核列表里**右键挑目录/文件**，或点工具栏「同步范围…」按钮管理：

- **只同步此项**：一键把范围设为当前这一项（范围外不再扫描）；
- **加入 / 移出同步范围**：把这一项加进或移出已有范围；
- **同步范围…** 对话框：查看、移除已挑的路径，或「恢复全量（清空范围）」。

设了范围之后：

- 本地只遍历这些文件夹/文件（文件夹自动含子目录）；
- 服务端**只列这些路径在「服务端文件仓库」与「客户端文件目录」里对应的位置**，其余目录一个请求都不发；
- 范围外的文件不读取、不计算哈希、不出现在差异审核里，也不会被发送；
- 统计栏与状态栏会显示当前范围，随时知道「这次到底在比什么」。

范围为空 = 全量同步（和以前一样），默认如此。快照按范围增量更新：范围内以本次扫描为准，范围外的旧记录原样保留，因此「发布待办」复用客户端文件读数时不会把上千个范围外文件误报成新增。

旧的「忽略审查」被「同步范围」取代（勾掉的目录不再需要单独维护，直接留在范围外即可）。

## 附：改名进度文案

改名项在发送时的进度不再显示成含糊的「上传 xxx」，而是：

- `改名 旧名 → 新名（目标）`
- `改名：删除旧文件 xxx`

发送前确认框也会写明「其中改名 N 个（上传新文件名 + 删除旧文件）」。
