# v1.2.9 更新内容

本版是三个修复：两个界面上的毛病，一个会让程序直接退出的崩溃。建议都更新。

## 一、修复「检查更新」界面把最旧的版本标成「最新」

「检查更新」结果里的「版本历史」列表，之前固定把**列表第一项**标成「（最新）」。但两个更新源的返回顺序并不一致：

- **GitHub** 是「新 → 旧」
- **Gitee** 是「旧 → 新」

而版本查询是 Gitee 优先，于是最旧的那个版本被标成了「（最新）」。

现在版本历史统一按**版本号**倒序排列（版本号解析不出的排最后，再按发布时间兜底），并且「（最新）」改为按版本号认定，不再依赖列表原有顺序——即使拿到乱序列表也不会标错。附带修好数字比较：`v1.2.10 > v1.2.9` 现在判定正确，不会退化成字符串比较。

## 二、修复偶尔冒出的「完全空白的窗口」

程序驻留托盘时，重复点开程序会触发「激活已运行实例窗口」。之前是取 `EnumWindows` 的**第一个**顶层窗口，再强行 `ShowWindow(SW_RESTORE)`。

问题是 `EnumWindows` 返回的是 **Z 序**（还会变化），而这个进程的顶层窗口除主窗口外还有 Qt 的内部辅助窗口（`Qt6xxScreenChangeObserverWindow`、`TrayIconMessageWindowClass`）和输入法窗口——一旦把它们（或把 Qt 认为「已隐藏」的主窗口）强行显示出来，就是一个**没有标题、没有任何内容、关掉也不会发生任何事情的空白窗口**。

现在改为把激活消息投递给该进程的**每个顶层窗口**：

- 主窗口自己会在 `nativeEvent` 里 `showNormal()/raise_()/activateWindow()`，托盘隐藏与最小化都能正确还原；
- Qt 的内部窗口没有对应处理，收到消息无副作用，也不会被显示出来。

实测（托盘状态调用激活）：可见窗口数 = 1 且就是主窗口，两个 Qt 内部窗口与输入法窗口仍全部隐藏，窗口总数不变（没有多出任何窗口）。

## 三、修复「检查更新」之后程序直接退出

点「检查更新…」（或到点自动检查）后，查询线程结束时会被 `deleteLater()` 销毁，但对象引用还留着；下次再检查走到 `self._update_thread.isRunning()` 就抛：

```
RuntimeError: Internal C++ object (UpdateCheckThread) already deleted
```

异常从 Qt 槽里逃出去，程序**直接退出**。打包成无控制台 exe 后界面上看不到任何提示，只在日志里留下一行「未捕获异常导致程序退出」。

现在线程结束时会先把引用清空（带身份校验，期间若已起新线程，不会被旧线程的清空动作误伤），之后再次检查可以正常起新线程。客户端与服务端的「检查更新」与「下载安装包」两处线程都已按同样方式处理。
