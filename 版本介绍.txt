# v1.2.8 更新内容

本版主要厘清两件事：**模组的运行环境**到底在哪一侧、以及**哪些文件该发给客户端**；并新增「模组版本检查」，更新模组时不再担心删错文件。

## 一、运行环境与「发给谁」彻底分开（重构）

之前把「客户端 / 服务端」压成一个值（仅客户端 / 仅服务端 / 双端），会丢信息：比如百科标注「客户端可选, 服务端需装」，被压成「仅服务端」后客户端就永远拿不到这个模组，玩家客户端之间内容可能不一致。

现在**运行环境是模组固有属性，客户端侧与服务端侧各自独立**，各自只可能是：需装 / 可选 / 无需 / 未判定。

- 「分析结果」列改为两侧分别显示，例如 `客户端：需装 ｜ 服务端：可选`
- 鼠标悬停可看完整判定依据（jar 元数据 / MC 百科原文）
- 元数据没写运行环境时不再瞎猜成「双端」，一律标「未判定」，交给腐竹判断

## 二、新增两个「可选也发」开关

放在「服务器设置」页（客户端模组关键词下方），按需打开：

- **「客户端可选」的模组也发给客户端**（按「客户端需装」处理）
- **「服务端可选」的模组也发到服务端**（按「服务端需装」处理）

「可选」本来就是装不装都行，这两个开关决定要不要一并同步过去。**单个模组仍可单独指定**：在差异审核列表右键改它的目标即可。

## 三、发布待办页只看客户端文件目录

先把两个目录的语义说清楚：

- 服务端根目录下的 `mods/` 等文件夹 → 存的是**运行环境在服务端**的模组与资源
- `client_files/` → 存的是**运行环境在客户端**的模组，以及一些别的要发给客户端的文件

这里区分的是「资源的运行环境」；至于「发给谁」，是另一个维度。据此：

- 「发布给客户端」的变更树**不再拿服务端 `mods/` 做对照**，只读 `client_files`，不再出现「服务端独有」那种干扰项
- **上传完立刻可见**：自动检测优先复用「更新服务端」页留下的快照，秒出结果，不再为了拿结果重新远程扫一遍（想强制重扫可点「重新检测」）
- 勾选了「本次不发布」的文件**彻底不参与检测**：不比对、不算远程哈希、也不会被误判成删除；状态栏会写明「已跳过 N 个」

## 四、新增：模组版本检查（「最新版本」列）

「更新服务端」页的「分析模组环境…」现在会顺带查一次模组的最新版本，在新增的「最新版本」列标出：

| 显示 | 含义 |
| --- | --- |
| 已是最新 | 本地版本就是渠道上的最新发布 |
| 有新版本 x.y.z | 渠道上有更新的发布（附上最新版本号） |
| 本地更新 | 本地版本比渠道最新还高（自制 / 测试版？） |
| 未查到 | 渠道里查不到或没法比较（不编造版本号） |

**用途**：更新模组时确认哪个文件才是旧版，避免在差异审核里删错文件。

实现要点：

- 渠道用 **Modrinth 官方 API** + **CurseForge**（走只读接口），不需要你填任何 key
- **不需要预先知道 MC 版本**：先按版本号定位「本地这一版」，用它所属的游戏版本圈定比较范围；文件名里带 `1.20.1` 这类游戏版本的会优先按它消歧（同一模组常常一个版本号对应多个 MC 版本）
- 优先用百科库里的精确项目标识（slug）查询，按名字搜也会校验标题完全一致才采用；**查不到就标「未查到」，不瞎猜**
- 「服务器设置」页新增开关「分析模组时顺带检查发布渠道的最新版本」，关掉就完全不联网
- 断网不会卡住：条数上限 + 整体 30 秒预算 + 连续查询无果立即放弃
- 版本检查**只是提示**，不参与发送目标判定
